DBMS Evaluator Explanatory Notes (Presentation Defense Guide):

1. Indexing Architecture: Cloud Firestore maintains automatic single-field B-Tree indexes for every field. When executing where("block", "==", "A") and where("capacity", ">=", 50), Google's query engine evaluates the query via a Zig-Zag Merge Join across individual field indexes. When ordering by a field different from the equality filter, a composite index (block ASC, capacity ASC) is required.
2. NoSQL Denormalization vs. SQL Joins: In traditional MySQL, retrieving room availability with period schedules requires a relational join (e.g. SELECT * FROM rooms JOIN schedules ON ...). In a distributed environment, cross-partition joins require expensive network RPC shuffles. Firestore embeds the 12-slot timetable matrix and facilities inside each document, guaranteeing an O(1) single-tablet fetch.
3. Strong Consistency (ACID): Unlike Cassandra or MongoDB which rely on eventual consistency, Firestore runs on Google Spanner. TrueTime atomic clocks and Paxos consensus provide linearizable, strongly consistent reads and serializable multi-document transactions.
